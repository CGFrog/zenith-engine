# Code map

Jump straight to an implementation without searching the tree. Paths are
relative to the repository root; include paths in code are rooted at `src/`
(`engine/scene/Scene.hpp`). **Symbols** are the types and functions to open
first. **Test** is the CTest name (`ctest --test-dir build -C Debug -R <name>`);
its source is `tests/<area>/<Name>Tests.cpp`. **Doc** is the reference page
with the full contract.

Sections:

1. [Find it fast](#find-it-fast): task or question → file, symbol, test.
2. [Call chains](#call-chains): startup, one frame, Play, module hot reload.
3. [Conventions an agent should know](#conventions-an-agent-should-know).
4. [Tests index](#tests-index).
5. [Source index](#source-index): every source file, one line each
   (generated by `tools/docs/code_index.py`).

Keep it current: when you add, move, or remove a source file, run
`python tools/docs/code_index.py`, and add a row to *Find it fast* for any new
capability. `--check` fails when the generated index is stale.

## Call chains

Function names are real; follow them in the files named.

### Game executable startup (`zenith`)

1. `main` → `run` in `src/main.cpp`: `initializeResourceLocator(argv[0])`.
2. `parseGameLaunchArguments` (`game/application/GameLaunch.*`): `--project`, `--scene`, `--verify-package`.
3. `loadLaunchProject` → `loadProjectConfig` (`engine/project/ProjectConfig.*`).
4. `loadRuntimeGameplay` (`game/application/RuntimeGameplay.*`) → `GameModule::load` (`engine/module/GameModule.*`) → module's `zenith_module_register(ModuleRegistrar&)` → `gameplayFromModule`; without a module, `linkGameplay` with the demo's registration.
5. `--verify-package` → `verifyPackage` (`game/application/PackageVerification.*`) and exit.
6. `Engine::init` (window, Vulkan renderer, physics, audio).
7. `ProjectApplication` (any module) or `DemoApplication` (the demo's module) → `Engine::run(application)`.
8. The application's scene `load` → `SceneDocument::load` → `GameplayRunner::start` (creates `GameServices`, publishes `SceneLoaded`).

### One frame (`Engine::run`, `src/engine/Engine.cpp`)

1. `InputManager::update` → `InputState`; resize/quit requests.
2. `ApplicationScene::update` → `GameplayRunner::update` → `GameServices::beginFrame`, `runGameplayPhase(Update)` (systems, then `zenith.behaviours`), timers, command flush.
3. Accumulate `min(dt, 0.1) × timeScale`; per fixed step: `ApplicationScene::fixedUpdate` (`runGameplayPhase(FixedUpdate)`, trigger/collision hooks first) → `PhysicsWorld::step` → `afterPhysicsStep` (`GameServices::publishPhysicsEvents`) → `InputManager::consumeFixedPresses`.
4. `PhysicsWorld::interpolate(scene, alpha)`.
5. `ApplicationScene::lateUpdate` (`runGameplayPhase(LateUpdate)`), animation update.
6. `Scene::updateWorldTransforms`.
7. `Renderer::beginUiFrame` → `GameUiContext::beginFrame` → `ApplicationScene::drawUi` (`runGameplayPhase(Ui)`) → `Renderer::drawGameUi`.
8. `Renderer::drawFrame` (records every pass; see [render flow](engine/graphics.md#render-flow)).
9. `AudioSystem::syncScene` / `setPlaybackRate` / `update`.
10. Deferred scene switch or quit; deferred asset collection.

### Editor startup (`zenith_editor`)

1. `src/editor/main.cpp`: resource locator, settings directory (`ZENITH_EDITOR_SETTINGS_DIR`), crash handler, `Engine::init`.
2. `EditorApplication` (`editor/application/EditorApplication.*`) → `Engine::run`.
3. No project argument → Project Hub (`editor/project/ProjectHub.*`); a project → `EditorSession` (`editor/application/EditorSession.*`).
4. `EditorSession` builds the operator registry from `editorOperatorFamilies()`, the default keymap, default menus and workspaces, loads the project's module through `GameModuleController::load` (`GameModuleHost::load`), and opens the startup scene.
5. Each frame: `EditorSession::update` (keymap dispatch, module edit systems via `GameModuleHost::runEditFrame` or Play stages) and `EditorSession::drawUi` (main menu, areas/panels, viewports).

### Pressing Play (`F5`)

1. Keymap → operator `play.start` (`application/EditorPlayback.cpp`) → `EditorPlayback::startPlay(context, target)` (the session's `m_playback`).
2. `EditorPlayback::enter`: `PhysicsWorld::clear`, `EditorPlayMode::enter` (snapshot the edit scene, clone the runtime scene), `GameModuleHost::startGameplay` (new `GameServices`), set audio, navigation settings, save store, publish `SceneLoaded`; `CommandHistory::crossBoundary(EnterPlayMode)`.
3. Target: active viewport → `ViewportPanel::beginGameView`; floating → a new floating Viewport area; standalone → `StandalonePlayer` runs `zenith --project <p> --scene <temp>` as a `ChildProcess`.
4. Each frame: the session's frame hooks forward to `EditorPlayback` (`update`, `fixedUpdate`, `afterPhysicsStep`, `lateUpdate`, `beginUiFrame`); `EditorPlayback::runGameplayStage` per stage → `GameModuleHost::runSystems(phase, ...)`; a fault → `stopFailedGameplay`.
5. `Shift+F5` → `play.stop` → `EditorPlayback::stopPlay` → `stop`: `GameModuleHost::stopGameplay` (behaviour `onDestroy`, services released), restore the edit scene.

### Building and hot reloading a module (`Ctrl+B`)

1. `build.run` (`operators/BuildOperators.*`) → `ProjectBuild` → `BuildRunner` (fast Ninja build in `<project>/.zenith/build`, else the CMake preset).
2. Output parsed by `CompilerOutputParser` → Build panel and `EditorDiagnostics`.
3. The module file changes → `GameModuleController::pollReload` → `GameModuleHost::reload(scene, assets, document)` (deferred while building, playing, or while prefab windows are open): serialize module components, `releaseModule` (editor extensions, services, behaviours), `GameModule::load` the new shadow copy, re-register, deserialize. A failed load keeps the data as JSON.

### Loading and saving a scene

- Save: `file.save` → `EditorDocument` → `SceneDocument::save` (atomic write via `engine/platform/PlatformServices.*`).
- Load: `SceneDocument::load` → parse → per-component `ComponentType` loaders with schema migrations → asset references resolved through the `AssetDatabase` (GUID first, then path) → prefab instances rebuilt by `PrefabSystem`.

## Conventions an agent should know

- **Layers.** `src/engine/` never includes from `editor/` or `game/`; the
  editor and game depend on the engine. Third-party types (Vulkan, SDL, Jolt,
  cgltf) stay private to their subsystem.
- **Explicit source lists.** Engine files go in `src/engine/CMakeLists.txt`
  (`zenith_engine`), editor files in `src/editor/CMakeLists.txt`
  (`zenith_editor_app`), game files in `src/game/CMakeLists.txt`, tests in
  `tests/<area>/CMakeLists.txt`. Nothing is globbed.
- **Results, not exceptions,** at recoverable boundaries: `SceneResult`,
  `SceneDocumentResult`, `AssetLoadResult<Handle>`, `PhysicsResult`,
  `GameModuleResult`, `OperatorResult`, `ProjectConfigResult`, ... each with
  `success`/`error` and `explicit operator bool`.
- **Handles.** Assets are generational handles (`ModelHandle`, `MeshHandle`,
  `MaterialHandle`, `TextureHandle`); audio uses clip/voice handles; render
  views and scenes use `RenderViewId`/`RenderSceneId`. Entities that outlive a
  frame are held as `SceneEntityId`, not `Entity`.
- **Reflection is explicit.** `Fields<T>().add("key", &T::member)`; component
  keys and field keys are persisted names — change them only with a schema
  version and a migration.
- **Component registration order** is fixed in
  `scene/BuiltInComponentTypes.cpp`; append, never reorder.
- **Module ABI.** Changing `SystemContext`, `ModuleRegistrar`, `GameServices`,
  `BehaviourContext`, a registered descriptor, or a component layout modules
  read bumps `ZENITH_MODULE_API_VERSION` (`engine/module/ModuleApi.hpp`).
- **Editor actions are operators** with stable ids (`object.duplicate`);
  menus and keys refer to the id. Families are registered one line each in
  `operators/EditorOperatorFamilies.cpp`; default keys in
  `operators/DefaultKeymap.cpp`; menus as data in `menus/DefaultMenus.cpp`.
- **Panels edit through `SceneEditing`** (undoable in Edit, live in Play);
  never write `CommandHistory` directly.
- **Theme.** Colours from `theme/EditorPalette`, sizes from `editorArtPixel`,
  controls from `theme/EditorWidgets`.
- **Naming.** Files are named after their main type (`PhysicsWorld.hpp` →
  `PhysicsWorld`); tests after what they cover (`PhysicsQueryTests.cpp` →
  `zenith_physics_queries`); built-in systems `zenith.<name>`; module systems
  `<module>.<name>`; event and resource keys `"<game>.<name>"`.
- **Coordinates.** Right-handed, +Y up, −Z forward, metres, radians in code;
  GLM column-major; `world = parentWorld * local`. Scene depth uses reversed Z
  (`graphics/DepthConvention.hpp`).
- **Engine exports.** `zenith_engine` is a shared library: functions export
  automatically; exported data needs `ZENITH_ENGINE_API`; don't call privately
  linked libraries (volk, Jolt, shaderc) from inline header code.
- **Style.** `.clang-format`; braces on every `if`; descriptive names.
