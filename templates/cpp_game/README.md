## Build the game module

The editor's **Build** panel runs the project's preset from this folder:

```powershell
cmake --preset zenith
cmake --build --preset zenith
```

The `zenith` preset configures `build/` with the generator and compiler the
Zenith engine was built with and builds the `{{BUILD_CONFIG}}` configuration.
A module only loads into an editor built with the same compiler and runtime,
so keep the two in step. `ZENITH_ROOT` (a cache variable, set in
`CMakePresets.json`) points at the Zenith build directory:

    {{ZENITH_ROOT}}

Point it at another configured and built Zenith build directory (or a Zenith
checkout whose `build/` is one) with `-DZENITH_ROOT=<path>` or by editing the
preset.

## Work on the game

1. Open the project in the editor (Project Hub, or `zenith_editor
   {{PROJECT_IDENTIFIER}}.zenith-project`) and press **Build** in the Build
   panel. The editor loads the module when the build finishes and reloads it
   after every later build.
2. Select the cube, choose **Add Component > Gameplay > Spinner**, and press
   `F5` to play: the spinner system turns it.
3. **Open in IDE** (Project Hub) opens this folder with the editor's IDE
   command (`ide.command` in the Build panel's settings). Build errors in the
   Build panel open at their line in the IDE.

Add a component by declaring its struct, describing its fields with
`Fields<T>` in a `ComponentTypeBuilder`, and registering it in
`zenith_module_register`; add a system with `registrar.addSystem`. New source
files go in `src/CMakeLists.txt`.
